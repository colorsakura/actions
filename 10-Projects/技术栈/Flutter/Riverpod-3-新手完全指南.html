第一部分：基础概念

1. 什么是状态管理？

生活比喻

想象你在管理一个图书馆：

  • 状态 = 书架上每本书的位置和数量
  • 状态管理 = 记录哪些书被借走、哪些书归还、更新书架布局的系统

在 Flutter 应用中：

  • 状态 = 应用中的数据（用户信息、设置、购物车等）
  • 状态管理 = 管理这些数据如何存储、更新、传递的工具

实际例子：

问题： 当应用变复杂时，状态会分散在各处，难以管理！

解决方案： Riverpod 帮你集中管理所有状态。

2. 为什么选择 Riverpod？

对比其他方案

方案优点缺点
setState简单、内置只能在组件内使用，难以共享状态
InheritedWidget内置、灵活代码复杂、容易出错
Provider流行、社区大不安全（运行时错误）
Riverpod安全、简单、强大学习曲线稍陡

Riverpod 的优势：

✅ 安全：编译时就能发现错误（不是运行时崩溃） ✅ 简单：代码少，易读易维护 ✅ 强大：支持异步、缓存、依赖注入 ✅ 灵活：任何地方都能访问状态，不需要 BuildContext ✅ 测试友好：容易写单元测试

Riverpod 3.0 新特性：

  • 🔄 自动重试失败的请求
  • 💾 离线缓存（实验性）
  • 🎯 更简单的 API
  • 🛠️ 更好的开发工具

3. Riverpod 核心概念图解

核心理念

Riverpod 的核心思想：Provider = 数据提供者

把它想象成自动售货机：

  • 你投入硬币（访问 Provider）
  • 它给你商品（返回数据）
  • 当货物更新时，所有观看它的人都会看到新货物

3.1 三个核心概念

    A[Provider<br/>数据提供者] --> B[Ref<br/>引用]
    A --> C[Consumer<br/>消费者]
    B --> D[读取/监听数据]
    C --> D
    D --> E[Widget 树更新]

sequenceDiagram
    participant Widget
    participant Ref
    participant Provider
    participant State

    Widget->>Ref: ref.watch(provider)
    Ref->>Provider: 请给我数据
    Provider->>State: 返回状态
    State-->>Ref: 数据更新时通知
    Ref-->>Widget: 通知重建
    Widget->>Widget: 更新 UI

新手常见疑问

Q1: 什么时候用 Provider，什么时候用 NotifierProvider？

简单回答

  • Provider - 只读数据（配置、常量）
  • NotifierProvider - 需要修改的数据（应用状态）

Q2: autoDispose 是什么？

简单回答

自动清理不再使用的 Provider，节省内存。

例子： 用户详情页面

  • 用户进入页面 → 加载数据
  • 用户离开页面 → 自动清理

Q3: family 是什么？

简单回答

让 Provider 可以接收参数。
