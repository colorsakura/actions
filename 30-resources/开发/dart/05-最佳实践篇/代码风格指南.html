Dart 代码风格指南

概述

本指南基于 Dart 官方代码风格规范，涵盖命名约定、格式化规则、文档注释和代码组织。遵循这些规范将使你的代码更易读、更易维护，并与 Dart 生态系统保持一致。

命名约定

类型命名（UpperCamelCase）

类、枚举、类型定义和泛型参数使用大驼峰命名法。

类型命名规则

  • 类名：MyClass, DatabaseConnection
  • 枚举：HttpStatus, UserRole
  • typedef：JsonObject, FilterCallback
  • 泛型：T, E, TKey, TValue

变量和成员命名（lowerCamelCase）

变量、参数、函数、成员使用小驼峰命名法。

变量命名规则

  • 变量：myVariable, userCount
  • 函数：getUserName, calculateTotal
  • 常量：pi, maxConnections
  • 私有成员：_privateField, _internalMethod()

库和文件命名（lowercase_with_underscores）

文件命名规则

  • 使用小写字母
  • 单词之间用下划线分隔
  • 文件名应与主要类名相关

行长度

风格违规警告

❌ 不要使用制表符缩进 ❌ 不要在一行写多条语句 ❌ 不要省略大括号

文档注释

文档注释语法

使用 /// 编写文档注释，支持 Markdown 格式。

文档注释最佳实践

  • 第一行是摘要：简短描述，以句号结尾
  • 使用 [引用]：引用其他 API 元素
  • 包含示例：使用代码块展示用法
  • 说明参数和返回值：清晰的参数说明
  • 记录异常：说明可能抛出的异常

类和成员文档

文档注释警告

❌ 不要使用单行注释编写文档

❌ 不要省略公共 API 的文档

Import 语句组织

Import 顺序

Import 组织规则

  1. dart: - Dart 核心库
  2. package: - 第三方包
  3. 相对路径 - 项目内文件
  4. 各部分内部按字母顺序排列
  5. 使用空行分隔各个部分

Import 别名和显示/隐藏

延迟加载

Import 最佳实践

  • 使用相对导入导入项目文件
  • 使用 package 导入导入包文件
  • 避免使用 ../ 超过两级
  • 使用 show 明确需要的内容
  • 使用 hide 排除不需要的内容
  • 为冲突的导入添加别名

代码组织

文件结构

文件组织建议

  1. 文档注释在前
  2. 按顺序排列：imports → exports → constants → classes
  3. 公共在前：公共成员在私有成员之前
  4. 相关内容分组：功能相关的代码放在一起

检查清单

在提交代码前，确保：

  • 所有标识符遵循命名约定
  • 代码已通过 dart format 格式化
  • 所有公共 API 都有文档注释
  • Import 语句按正确顺序组织
  • 没有使用制表符缩进
  • 行长度不超过 80 字符
  • 布尔变量使用 is/has 前缀
  • 私有成员使用下划线前缀
