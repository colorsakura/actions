1. 变量与类型

变量声明方式

变量声明方式

概述

Dart 提供了多种变量声明方式，包括 var、final、const、late 以及显式类型声明。理解它们的区别和使用场景是编写高质量 Dart 代码的基础。

声明方式对比

1. var - 类型推导

var 让编译器根据初始值推导变量类型，推导后类型不可更改。

注意

  • var 不是动态类型，推导后类型固定
  • 使用 var 时应该立即初始化
  • 避免使用未初始化的 var，会推导为 dynamic

2. final - 运行时常量

final 声明的变量只能赋值一次，但可以在运行时确定值。

使用场景

  • 运行时计算的值
  • 需要延迟初始化的变量
  • 不需要修改的变量

3. const - 编译时常量

const 声明的变量必须是编译时常量，在编译时确定值。

const 限制

  • 必须在编译时能确定值
  • 不能使用 DateTime.now() 等运行时值
  • const 对象的所有字段必须是 final
  • const 集合的所有元素必须是 const

4. late - 延迟初始化

late 用于声明延迟初始化的变量，可以是非空类型。

late 使用建议

  • 确保 late 变量在使用前被初始化，否则抛出 LateError
  • 用于延迟初始化可以提升性能
  • 处理循环依赖时很有用

5. 显式类型声明

明确指定变量类型，提高代码可读性。

何时使用显式类型

  • 类型不明显时
  • 公共 API
  • 需要明确类型约束时

声明方式决策树

graph TD
    A[声明变量] --> B{值在编译时确定?}
    B -->|是| C[const]
    B -->|否| D{需要修改?}
    D -->|否| E{初始化时机?}
    D -->|是| F[var 或显式类型]
    E -->|立即| G[final]
    E -->|延迟| H[late / late final]
    C --> I[编译时常量]
    G --> J[运行时常量]
    H --> K[延迟初始化]
    F --> L[可变变量]

最佳实践

选择建议

  1. 优先使用 var：类型明显时使用

  2. 使用 final 替代 var：当变量不需要修改时

  3. 使用 const：编译时常量

  4. 显式类型：类型不明显或需要约束时

  5. 谨慎使用 late：只在必要时使用

常见陷阱

陷阱 1：var 不是动态类型

陷阱 2：const 的不可变性

陷阱 3：late 变量未初始化

陷阱 4：const 不能使用运行时值

性能考虑

性能特点

  • const：性能最好，编译时展开，无运行时开销
  • final：性能与普通变量相同，但确保不可变
  • var：无性能损失，编译时推导类型
  • late：首次访问时有初始化开销

Dart 类型系统

Dart 类型系统

概述

Dart 是强类型语言，支持类型推导和空安全。理解 Dart 的类型系统对于编写类型安全、健壮的代码至关重要。

类型系统特点

Dart 的类型系统具有以下特点：

  • 强类型：编译时进行类型检查
  • 类型推导：可以自动推导变量类型
  • Sound null safety：空安全保证
  • 可选类型：类型注解是可选的（但推荐使用）

类型最佳实践

类型使用建议

  1. 优先使用类型推导：类型明显时

  2. 显式声明复杂类型：提高可读性

  3. 避免 dynamic：保持类型安全
