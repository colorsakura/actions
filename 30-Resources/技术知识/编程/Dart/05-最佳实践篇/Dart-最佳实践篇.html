1. 代码风格指南

Dart 代码风格指南

Dart 代码风格指南

概述

本指南基于 Dart 官方代码风格规范，涵盖命名约定、格式化规则、文档注释和代码组织。遵循这些规范将使你的代码更易读、更易维护，并与 Dart 生态系统保持一致。

命名约定

类型命名（UpperCamelCase）

类、枚举、类型定义和泛型参数使用大驼峰命名法。

类型命名规则

  • 类名：MyClass, DatabaseConnection
  • 枚举：HttpStatus, UserRole
  • typedef：JsonObject, FilterCallback
  • 泛型：T, E, TKey, TValue

变量和成员命名（lowerCamelCase）

变量、参数、函数、成员使用小驼峰命名法。

变量命名规则

  • 变量：myVariable, userCount
  • 函数：getUserName, calculateTotal
  • 常量：pi, maxConnections
  • 私有成员：_privateField, _internalMethod()

库和文件命名（lowercase_with_underscores）

文件命名规则

  • 使用小写字母
  • 单词之间用下划线分隔
  • 文件名应与主要类名相关

2. 错误处理模式

Dart 错误处理模式

Dart 错误处理模式

概述

错误处理是编写健壮 Dart 应用的关键。Dart 提供了完善的异常处理机制，包括 Exception 和 Error 类型，以及 try-catch-finally 语句。本篇深入探讨 Dart 的错误处理模式和最佳实践。

Exception vs Error

核心区别

  • Exception：可预料的异常情况，程序应该尝试恢复
  • Error：严重的系统级错误，通常不应该被捕获（如 StackOverflowError）

  3. 考虑异常类型：Exception vs Error

try-catch-finally

  • try：包含可能抛出异常的代码
  • catch：处理特定类型的异常
  • finally：无论是否发生异常都执行的代码

  2. 提供有用的错误信息：帮助调试和用户理解
  3. 及时释放资源：使用 finally 确保清理

3. 性能优化

性能优化

性能优化

概述

性能优化是编写高质量 Dart 应用的重要环节。本主题涵盖避免不必要的对象创建、const vs final 的性能影响、集合操作优化和异步代码性能优化，帮助你编写更高效的 Dart 代码。

学习目标

完成本主题学习后，你将能够：

  • 识别并避免不必要的对象创建
  • 正确使用 const 和 final 优化性能
  • 选择合适的集合类型和操作方式
  • 编写高性能的异步代码

在学习本主题之前，建议已掌握：

  • Dart 面向对象篇 - 类和构造函数

避免不必要的对象创建

操作：使用对象池重用对象

对象池（Object Pooling）是一种避免频繁创建和销毁对象的技术，特别适用于重量级对象。

操作：使用 const 构造函数

const 构造函数创建编译时常量，避免运行时对象创建。

对象重用原则

  • 频繁使用的对象：使用全局常量或对象池
  • 不可变数据：优先使用 const 构造函数
  • 可重用对象：使用 clear() 而非重新创建
  • 大对象：延迟初始化，按需创建

const vs final 的性能影响

操作：选择 const 或 final

理解 const 和 final 的性能差异对于优化代码至关重要。

操作：const 构造函数的性能优势

const vs final 选择指南

  • 编译时常量：使用 const（值在编译时已知）
  • 运行时常量：使用 final（值在运行时确定）
  • 集合字面量：尽可能使用 const
  • 构造函数：实现 const 构造函数以支持常量优化

集合操作的性能考虑

操作：选择合适的集合类型

不同的集合类型有不同的性能特征。

操作：使用懒加载和批量操作

集合操作优化建议

  • 频繁查找：使用 Set 而非 List（O(1) vs O(n)）
  • FIFO 操作：使用 Queue
  • 大数据集：使用懒加载（Iterable）
  • 已知大小：预分配容量避免扩容
  • 批量操作：使用 List.generate 而非循环 add

异步代码的性能优化

操作：避免不必要的异步

不是所有操作都需要异步，不必要的 async 会增加开销。

操作：优化 async/await 使用

操作：Stream 优化

异步优化建议

  • 避免过度 async：同步操作不要用 async
  • 并行执行：使用 Future.wait 并行独立操作
  • 批量处理：批量启动异步任务，然后等待全部完成
  • Stream 选择：多订阅使用广播流
  • 取消未完成的操作：使用 Future.any 或取消 token

  • Benchmark：使用 package:benchmark_harness

性能优化检查清单

  • 避免在循环中创建对象
  • 使用 const 构造函数创建常量
  • 选择合适的集合类型（List/Set/Queue）

最佳实践总结

核心优化原则

  1. 对象重用：使用对象池、const 构造函数、对象缓存
  2. 选择正确类型：const vs final、List vs Set、sync vs async
  3. 批量操作：使用 List.generate、Future.wait、批量 API
  4. 懒加载：延迟初始化、Iterable 懒计算
  5. 测量优先：使用 DevTools 分析，不要过早优化

过度优化的危险

  • 可读性优先：除非性能问题严重，否则优先考虑代码清晰
  • 测量真实场景：微基准测试可能误导，关注实际应用性能
  • 权衡取舍：内存 vs CPU、开发效率 vs 运行效率
  • 保持简单：简单的代码往往更快且更容易维护

4. 常见反模式

Dart 常见反模式

Dart 常见反模式

概述

本文总结 Dart 编程中的常见反模式（Anti-patterns），这些是应该避免的不良编程实践。识别并避免这些反模式将帮助你写出更安全、更高效、更易维护的代码。

学习目标

完成本章学习后，你将能够：

  • 识别并避免过度使用 dynamic 类型
  • 正确使用 async/await 处理异步操作
  • 充分利用 Dart 空安全特性
  • 预防和修复常见的内存泄漏问题

1. 过度使用 dynamic 类型

反模式：过度使用 dynamic

dynamic 类型会绕过编译时类型检查，失去类型安全的好处，增加运行时错误的风险。

❌ 不好的实践

✅ 正确的做法

最佳实践

  1. 优先使用具体类型：明确定义变量和参数类型
  2. 使用类型类：为复杂数据结构创建类
  3. 使用泛型：保持类型安全的同时提供灵活性
  4. 限制 dynamic 使用：仅在必要时使用（如 JSON 解析中间步骤）

2. 不恰当的 async/await 使用

反模式：滥用 async/await

不必要的 async 关键字会增加性能开销，不正确的 await 使用可能导致阻塞。

❌ 不好的实践

✅ 正确的做法

最佳实践

  1. 同步返回不用 async：直接返回值更高效
  2. 使用 Future.wait：并行执行独立异步操作
  3. 正确使用 await：需要结果的异步操作必须 await
  4. 避免阻塞循环：使用 Future.wait 或 asyncExpand

3. 忽视空安全

反模式：忽视空安全

Dart 2.12+ 引入了空安全特性，忽视这些特性会导致运行时空指针异常。

❌ 不好的实践

✅ 正确的做法

最佳实践

  1. 使用 ?. 操作符：安全访问可空对象成员
  2. 使用 ?? 运算符：为空值提供默认值
  3. 避免 ! 操作符：仅在确定值非空时使用
  4. 参数默认值：为可空参数提供合理默认值
  5. 使用 late：延迟初始化非空变量

4. 内存泄漏

反模式：内存泄漏

不正确的资源管理会导致内存泄漏，特别是在长时间运行的应用中。

❌ 不好的实践

✅ 正确的做法

最佳实践

  1. 取消 Stream 订阅：使用 StreamSubscription.cancel()
  2. 取消 Timer：使用 Timer.cancel()
  3. 及时释放资源：不再需要的对象设为 null
  4. 使用 WeakReference：避免闭包循环引用
  5. Flutter 中正确清理：在 dispose() 中释放资源
