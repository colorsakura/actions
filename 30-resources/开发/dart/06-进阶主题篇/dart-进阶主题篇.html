1. 内存管理

Dart 内存管理

Dart 内存管理

概述

Dart 采用自动内存管理机制，通过垃圾回收器 (Garbage Collector) 自动回收不再使用的对象。理解 Dart 的内存管理机制对于编写高性能应用、避免内存泄漏至关重要。

栈与堆的区别

  • 栈: 存储局部变量、函数参数、返回地址，自动分配和释放
  • 堆: 存储对象实例，通过垃圾回收器管理

垃圾回收机制

Dart 使用分代垃圾回收器 (Generational Garbage Collector),基于以下观察：大多数对象都是短命的。

实践建议

内存管理最佳实践

  1. 优先使用 const: 减少对象创建
  2. 及时释放资源: 取消订阅、清空引用
  3. 避免过早优化: 先确保代码正确，再优化性能
  4. 使用 DevTools: 定期分析内存使用情况
  5. 警惕全局状态: 全局变量容易导致内存泄漏
  6. 合理使用缓存: 配合 WeakReference 实现自动清理

总结

Dart 的自动内存管理大大简化了开发工作，但理解其内部机制对于编写高性能应用仍然重要。关键要点：

  • Dart 使用分代垃圾回收器，优化了大多数对象短命的场景
  • WeakReference 和 Expando 是避免内存泄漏的强大工具
  • 使用 DevTools 可以有效检测和诊断内存问题
  • 合理的代码设计和资源管理是避免内存泄漏的根本方法
  • 性能优化应基于实际测量，而非猜测

掌握这些知识后，你将能够编写更高效、更稳定的 Dart 应用程序。

2. 并发模型

Dart 并发模型

Dart 并发模型

核心概念

Dart 采用基于 Isolate 的并发模型，每个 Isolate 拥有独立的内存堆，通过消息传递进行通信。这种设计避免了传统多线程编程中的竞态条件和数据竞争问题，同时保持了高效的并发处理能力。

学习目标

完成本文学习后，你将能够：

  • 理解 Dart 的单线程事件循环模型
  • 掌握 Isolate 的创建和通信机制
  • 使用 SendPort/ReceivePort 进行跨 Isolate 通信
  • 理解并发安全的概念和实现
  • 选择合适的并发编程策略

3. Dart VM 原理

Dart VM 原理

Dart VM 原理

概述

Dart VM（虚拟机）是执行 Dart 代码的核心运行时环境。它提供了即时编译（JIT）和提前编译（AOT）两种模式，支持热重载、增量编译和代码优化，为开发体验和生产性能提供了最佳平衡。

词法分析与语法分析

2. JIT 编译模式

JIT（Just-In-Time）编译

JIT 编译在运行时将 Dart 代码编译为本地机器码。它支持：

  • 热重载（Hot Reload）
  • 动态类型检查
  • 增量编译
  • 开发时快速迭代

JIT 执行流程：

Dart 源码
    ↓
解析为 AST
    ↓
编译为字节码
    ↓

    ↓
热点识别
    ↓
JIT 编译为机器码
    ↓
优化执行

3. AOT 编译模式

AOT（Ahead-Of-Time）编译

AOT 编译在构建时将 Dart 代码编译为本地机器码。它提供：

  • 快速启动
  • 稳定性能
  • 代码混淆
  • 生产环境优化

AOT 执行流程：

Dart 源码
    ↓
解析为 AST
    ↓
全局分析
    ↓
树摇（Tree Shaking）
    ↓
内联优化
    ↓
编译为机器码
    ↓
链接为可执行文件

进阶主题注意点

  1. Isolate 开销：创建 Isolate 有性能开销，不要滥用
  2. 内存泄漏：注意对象引用，尤其是闭包中的引用
  3. GC 影响：频繁的对象创建会触发 GC，影响性能
  4. 平台差异：Web 和 Native 平台的 VM 实现不同
