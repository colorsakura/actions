性能优化

概述

性能优化是编写高质量 Dart 应用的重要环节。本主题涵盖避免不必要的对象创建、const vs final 的性能影响、集合操作优化和异步代码性能优化，帮助你编写更高效的 Dart 代码。

学习目标

完成本主题学习后，你将能够：

  • 识别并避免不必要的对象创建
  • 正确使用 const 和 final 优化性能
  • 选择合适的集合类型和操作方式
  • 编写高性能的异步代码

前置知识

在学习本主题之前，建议已掌握：

  • Dart 基础篇 - 对象和基本类型
  • Dart 面向对象篇 - 类和构造函数
  • Dart 进阶特性篇 - 异步编程

避免不必要的对象创建

操作：使用对象池重用对象

对象池（Object Pooling）是一种避免频繁创建和销毁对象的技术，特别适用于重量级对象。

操作：使用 const 构造函数

const 构造函数创建编译时常量，避免运行时对象创建。

对象重用原则

  • 频繁使用的对象：使用全局常量或对象池
  • 不可变数据：优先使用 const 构造函数
  • 可重用对象：使用 clear() 而非重新创建
  • 大对象：延迟初始化，按需创建

const vs final 的性能影响

操作：选择 const 或 final

理解 const 和 final 的性能差异对于优化代码至关重要。

操作：const 构造函数的性能优势

const vs final 选择指南

  • 编译时常量：使用 const（值在编译时已知）
  • 运行时常量：使用 final（值在运行时确定）
  • 集合字面量：尽可能使用 const
  • 构造函数：实现 const 构造函数以支持常量优化

集合操作的性能考虑

操作：选择合适的集合类型

不同的集合类型有不同的性能特征。

操作：使用懒加载和批量操作

集合操作优化建议

  • 频繁查找：使用 Set 而非 List（O(1) vs O(n)）
  • FIFO 操作：使用 Queue
  • 大数据集：使用懒加载（Iterable）
  • 已知大小：预分配容量避免扩容
  • 批量操作：使用 List.generate 而非循环 add

异步代码的性能优化

操作：避免不必要的异步

不是所有操作都需要异步，不必要的 async 会增加开销。

操作：优化 async/await 使用

操作：Stream 优化

异步优化建议

  • 避免过度 async：同步操作不要用 async
  • 并行执行：使用 Future.wait 并行独立操作
  • 批量处理：批量启动异步任务，然后等待全部完成
  • Stream 选择：多订阅使用广播流
  • 取消未完成的操作：使用 Future.any 或取消 token

性能分析工具

操作：使用 DevTools 分析性能

性能分析工具

  • Dart DevTools：CPU 性能分析、内存分析
  • Timeline：可视化执行时间线
  • Benchmark：使用 package:benchmark_harness
  • ** Observatory**：内存和性能监控

避免这些性能陷阱

1. 过度使用字符串拼接

2. 在热路径使用反射

3. 不必要的类型转换

4. 过度的函数调用开销

代码审查清单

性能优化检查清单

  • 避免在循环中创建对象
  • 使用 const 构造函数创建常量
  • 选择合适的集合类型（List/Set/Queue）
  • 避免不必要的 async/await
  • 使用 Future.wait 并行执行独立操作
  • 使用 StringBuffer 拼接大量字符串
  • 避免在热路径使用反射
  • 使用懒加载处理大数据集
  • 预分配已知大小的集合
  • 使用 Dart DevTools 分析性能瓶颈

最佳实践总结

核心优化原则

  1. 对象重用：使用对象池、const 构造函数、对象缓存
  2. 选择正确类型：const vs final、List vs Set、sync vs async
  3. 批量操作：使用 List.generate、Future.wait、批量 API
  4. 懒加载：延迟初始化、Iterable 懒计算
  5. 测量优先：使用 DevTools 分析，不要过早优化

过度优化的危险

  • 可读性优先：除非性能问题严重，否则优先考虑代码清晰
  • 测量真实场景：微基准测试可能误导，关注实际应用性能
  • 权衡取舍：内存 vs CPU、开发效率 vs 运行效率
  • 保持简单：简单的代码往往更快且更容易维护
