Flutter Riverpod 完全指南

概述

Riverpod 是 Flutter 的一个编译安全、类型安全的状态管理库，是 Provider 包的重构版本。它不需要 BuildContext，支持组合、依赖注入和测试，是 Flutter 社区推荐的状态管理方案之一。

一、Riverpod 简介

1.1 什么是 Riverpod？

Riverpod（ReverSED Povider Dependency）是 Flutter 的响应式缓存和状态管理框架，具有以下特点：

主要特性

  • 编译安全：在编译时捕获错误，而不是运行时
  • 无需 BuildContext：可以在任何地方访问状态
  • 自动依赖追踪：只有依赖的 provider 变化时才重建
  • 支持组合：providers 可以相互组合使用
  • 可测试：易于单元测试和集成测试
  • 内置异步支持：优雅处理 Future 和 Stream

1.2 Riverpod vs Provider

特性ProviderRiverpod
编译安全❌ 运行时错误✅ 编译时检查
需要 BuildContext✅ 必须❌ 可选
自动依赖管理❌ 手动处理✅ 自动
异步支持⚠️ 有限✅ 完善
Provider 组合❌ 困难✅ 原生支持

1.3 Riverpod 版本

Riverpod 主要有三个版本：

版本选择

  • Riverpod 1.x：经典版本，使用 ProviderContainer
  • Riverpod 2.x：增加了代码生成和更多功能
  • Riverpod 3.x：最新版本（2025），重要的 API 简化和新特性

本文档基于 Riverpod 3.x

3.0 重大变更

Riverpod 3.0 是一个重大更新，包含一些生命周期变更，可能会影响现有应用。升级时请仔细参考迁移指南。

二、Riverpod 3.0 新特性

2.1 重大更新概览

Riverpod 3.0 是一个重要的里程碑，包含了许多期待已久的功能、bug 修复和 API 简化：

核心亮点

  • ✅ 离线持久化（实验性） - Providers 可以持久化到本地数据库
  • ✅ Mutations（实验性） - 新机制让 UI 对副作用做出反应
  • ✅ 自动重试 - 失败时自动重试，支持指数退避
  • ✅ Ref.mounted - 类似 BuildContext.mounted，但用于 Ref
  • ✅ 泛型支持（代码生成） - 生成的 providers 可以定义类型参数
  • ✅ 暂停/恢复支持 - 暂停/恢复监听器
  • ✅ 公共 API 统一 - 行为统一，重复接口融合
  • ✅ Provider 生命周期变更 - 更符合现代代码的行为
  • ✅ 新的测试工具 - 更便捷的测试 API
  • ✅ AsyncValue 改进 - 现在是 “sealed”，支持模式匹配
  • ✅ 静态安全作用域 - 检测缺失的 overrides

四、核心概念

4.1 Provider 的本质

Provider 是一个只读对象，用于：

  • 访问状态
  • 计算派生状态
  • 与外部系统交互（API、数据库等）

关键组件：

  • ref：Provider 的引用，用于访问其他 providers 和监听生命周期
  • 返回值：Provider 暴露的值

十一、常见问题

11.1 Riverpod vs Provider 选择？

选择建议

  • 新项目：使用 Riverpod 3.x（最新版本）
  • 学习：Riverpod 有更好的文档和社区支持
  • 代码生成：Riverpod 3.x 的代码生成功能强大
  • 迁移：可以从 Provider 或 Riverpod 2.x 逐步迁移到 3.x

从 2.x 升级到 3.x

如果你的项目使用 Riverpod 2.x，可以逐步升级到 3.x。主要的变更包括：

  • StateProvider 等移到 package:riverpod/legacy.dart
  • AutoDisposeRef 等接口统一为 Ref
  • 所有 updateShouldNotify 现在使用 ==
  • AsyncValue 的 valueOrNull 改为 value

总结

Riverpod 3.x 是一个强大、类型安全、易于测试的 Flutter 状态管理解决方案。

核心要点（3.x 更新）

  1. 推荐使用 Notifier + 代码生成

    • 简单状态 → Notifier + @riverpod
    • 异步操作 → AsyncNotifier + @riverpod
    • Legacy providers → 仅用于兼容，应迁移

  2. 利用 3.x 新特性

    • Ref.mounted - 检查 provider 是否挂载
    • 自动重试 - 失败时自动重试
    • Mutations - UI 对副作用做出反应
    • 离线持久化 - 实验性功能
    • AsyncValue 改进 - sealed 类型、进度支持

  3. 遵循最佳实践

    • 使用代码生成减少样板代码
    • 使用 select 优化性能
    • 正确处理资源释放和生命周期
    • 分离业务逻辑和 UI
    • 使用 ProviderContainer.test 简化测试

通过掌握 Riverpod 3.x，你可以构建出可维护、可测试、高性能的 Flutter 应用！
